# Open Library as the book metadata source; a book is a work, not an edition

Book metadata (titles, covers, years, authors) comes from the Open Library API. A catalog-backed book is an Open Library work, and its External Reference is (openlibrary, book, the work ID). Editions, ISBNs and page counts are not stored, so every edition and translation of a work is the same Media Item, and a User's Log Entries for "Voroshilovgrad" and for "Ворошиловград" are one Item History. Open Library needs no key, and the Internet Archive "does not assert any new copyright or other proprietary rights over any of the material in the Open Library database", so it fits ADR-0001 and needs no licence of the kind ADR-0004 takes on for TMDB. Its work/edition model matches ADR-0005's Media Item. (Facts about Open Library in this ADR were checked against its developer pages and API on 2026-11-09.)

## Considered Options

Google Books was rejected. It has editions only, with no work to stand for all of them, so one book would split into many Media Items. Its default quota is small. Its branding terms forbid altering, grouping or mixing its results, which Search does when it puts a User's own books first under "In your Saved".

## Consequences

- **Identification.** Every request sends a `User-Agent` naming TasteTrack and the Operator's contact, as in Open Library's own example: `TasteTrack (<contact>)`. The contact is read from Worker configuration, never from code, since the repo is public and each deployment has its own Operator. Identified requests get three times the default limit: 3 requests a second instead of 1. Open Library also asks clients to cache responses and not to bulk-download through the API, which the cache below does.
- **Covers** are requested by cover ID only (`covers.openlibrary.org/b/id/<id>-<size>.jpg`), never by ISBN. Lookups by ISBN, OCLC or LCCN are limited to 100 per IP every 5 minutes and answer 403 past that, a limit a shared IP such as a Worker's can reach without us; lookups by cover ID (or OLID) are not limited. The medium size (M) is for thumbnails and the large one (L) for grids and the book page. A work without a cover shows a book placeholder. The UI credits Open Library with a link next to the TMDB notice.
- **Search** makes one call for works. A query containing a Cyrillic letter adds `lang=uk`, which "influences but doesn't exclude search results": works with a Ukrainian edition rank first and show it. The language filter (`language:ukr` in the query) is never used, because it excludes works without a Ukrainian edition, and Open Library holds some Ukrainian works only in translation: "Ворошиловград" must still find "Voroshilovgrad".
- **Titles** fit ADR-0004's three: the Original Title is the work's title, and the English and Ukrainian Localized Titles are the titles of an edition in `eng` and in `ukr`. A work with no edition in a language has no Localized Title in it. Display follows the same rules as films. Adding a book makes two calls, which fill the three titles, the authors and the cover. Both are searches for the work by its key, one asking for its Ukrainian edition and one for its English one: only search gives a work with its authors' names, its first-published year and its edition in a language, where the work's own record names authors by key and its editions come in pages. (Checked 2026-11-10.)
- **Authors** are cached metadata, names for display, not a domain entity: there are no author pages, and no filtering or sorting by author. A Manual Media Item of type book may carry authors too, as User data.
- **Cache.** Book metadata lives in the same D1 cache as films, keyed by External Reference, with what only one Media Type has kept in a type-specific part. It follows ADR-0004's rules: filled on add, no refresh-on-read, refreshed by the cron, and disposable. Two differ:
  - **No hard expiry for books.** ADR-0004's 90 days come from TMDB's terms, and Open Library sets no limit, so how long an entry may be kept is a property of its source: 90 days for TMDB, none for Open Library. A book entry the cron can't refresh keeps showing, which is what carries books through an outage of weeks.
  - **In Progress counts as a reference.** Entries referenced by a Log Entry, a List Item or an In Progress are refreshed; only entries none of them references are deleted. This holds for every Media Type.
- **Cron budget.** Workers Free allows 50 subrequests an invocation, so the cron counts its batch in subrequests, not entries: 40 a run across all sources, where a film costs one and a book two. This replaces ADR-0004's batch of up to 40 entries a run.
- **Merged works.** When Open Library merges a work into another, search no longer has the old ID, and its record answers 200 with a redirect to the work it became. Reads follow it, at the cost of two more calls, which the cron's budget has room for, and the stored External Reference is not rewritten. Two Media Items whose works were merged stay two.
- **Unavailable books.** Only a work Open Library answers 404 for, or has deleted, counts toward unavailability, under ADR-0004's rule of 3 checks at least 24 hours apart. A redirect is a merge, never unavailability. Open Library needs no key, so a 403 means it is blocking us: it alerts the Operator and never triggers conversion. Anything else, such as a 429, a 5xx or a timeout, is temporary. Detection and conversion come later, for books as for films; a converted book copies its title, year and authors.
- **Coverage is patchy, and the data messy.** 6 of 11 well-known Ukrainian books were found. Translators are listed among a work's authors, and some Ukrainian works are titled in transliteration, so their Original Title is in Latin letters and the Ukrainian edition gives the Cyrillic line. A book Open Library doesn't have is added as a Manual Media Item. The Internet Archive was down for weeks in October 2024; the cache keeps books already added showing through an outage like that.
