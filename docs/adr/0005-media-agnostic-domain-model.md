# Media-agnostic domain model from day one

Only films ship in the MVP, yet the domain model is built around a generic Media Item with a Media Type, not around "Film". Books follow films (ADR-0011), then series (ADR-0004), then games (ADR-0012), then albums, songs and artists (ADR-0013), each behind its External Source, and retrofitting a film-shaped schema and vocabulary later would mean a data migration and a rename across the whole codebase. (Revised 2026-11-09, when books were specified, 2026-11-15, when series were, 2026-11-19, when games were put before albums, #248, 2026-11-21, when albums were, #266, 2026-11-22, when songs were, #279, and 2026-11-24, when artists were, #298.) The order is films, books, series, games, albums, songs, artists.

## Consequences

- Domain terms avoid film-only words: Log Entry not "watch", Revisit not "rewatch", Backlog not "watchlist". The UI uses the media-specific wording for each Media Type.
- A Media Item does not have to come from an External Source: Manual Media Items have no External Reference and belong to the User who created it.
- Each List and each Backlog has one Media Type. Mixed-type Lists may come later, so nothing should assume a List's type is fixed forever at the data level.
- A catalog-backed Media Item is a work, not an edition: a translation or another edition of a work is the same Media Item.
- A Media Type can be **light**: kept only in Lists, never in a Backlog, so keeping one of its Media Items is one step. A light Media Type has no Backlog, In Progress, Progress, Log Entries or Thoughts, so its Library is always empty. The server refuses to create any of them for it, as a mismatch. Its List Items, Notes, order and Share Links are every other Media Type's. Songs are the first light Media Type, and artists the second. (Added 2026-11-22, with songs, #279; revised 2026-11-24, with artists, #298, when a light Media Type could also be kept in Favourites.)
- A Media Type can have **Favourites**, a second kind of system List beside the Backlog: one per User per Media Type, ordered by the User, holding at most 100 List Items. Like the Backlog, it can't be deleted or renamed. A **Like** puts a Media Item at its end, and taking the Like back removes its List Item, so the List's order is the User's ranking and there is no separate Like record. The List is created on the User's first Like. A 101st Like is refused with an error the UI shows. Its Notes, order and Share Links are any List's, and a Share Link to Favourites says it is one, so that its List Items are shown with their places. Like and Favourites are one model for every Media Type, but for now only artists, a light Media Type, have them: the server refuses a Like for any other Media Type as a mismatch. (Added 2026-11-24, with artists, #298.)
- In Progress is a state of its own, shared by every Media Type that needs one, separate from Log Entries and the Backlog.
- How far along a User is, their Progress, is one optional value on In Progress, shaped by Media Type: for a series, the last episode watched; for a book, the page the User is on and, optionally, how many pages their edition has, both the User's own rather than the catalog's, since a work has many editions; a Media Type with no shape has no Progress. Only the latest value is kept, with no history of changes. Finishing or abandoning a Media Item ends its In Progress, and the Progress goes with it; a Log Entry never carries Progress. The server checks a Progress only for its shape and range, never against the cache, which is disposable (ADR-0004) and can lag behind what has been released.
- A Thought, a User's dated free text about a Media Item, is one model for every Media Type that isn't light. It carries a copy of the Progress of the moment it was written, in its Media Type's shape. That copy is the User's own text, set by the client and changed only by the User, never updated from In Progress, so "only the latest Progress is kept" still holds for In Progress. (Added 2026-11-16, with Thoughts, #240.)
- Each External Source sits behind one catalog source module. Shared code reaches metadata only through the shared cache and the registry that maps each Media Type to its source, never by calling a source directly.
- Some MVP code is more general than films alone require; that is deliberate.
